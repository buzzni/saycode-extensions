# Saycode Slack 채널 (`buzzni.slack`)

사내 시험용 Slack 앱의 Socket Mode 연결로 Saycode 세션을 시작·이어가는 Extension입니다.

**현재 상태**: SDK 단위 테스트·패킹 완료. 소켓 연결·계정(app/team) 확인·봇 멘션 검증 정규화는 구현되어
패킹된 아티팩트 기준 통합 테스트(설치 app/team 확인 → 멘션 `/pair` → `/projects`, 세션 선택·후속 프롬프트
안내 경로)로 확인됐습니다. **다만 이는 로컬 패키지 통합 검증이며, 실제 Electron sandbox 안에서의 동작과
실제 Slack 봇을 통한 라이브 확인은 아직 이뤄지지 않았습니다.** 승인 버튼(T22)과 Desktop 종료 후 상시
수신은 별도로 진행 중입니다. 실제 연결 가능 여부는 Desktop 채널 설정 화면에서 확인하세요.

## 준비물

- 이 용도로만 쓸 전용 Slack 앱, 설치 권한이 있는 워크스페이스.
- Desktop에 로그인된 Saycode 계정.

## Desktop에 설치

이 폴더를 패키징한 `.saycode-extension` 파일을 전달받았다면, Desktop **설정 → 확장 → 로컬 파일 설치**로
설치한 뒤 **활성화**를 눌러 요청 권한을 확인하고 승인하세요(확장 ID: `buzzni.slack`). 설치·활성화 전에도
"메신저 채널" 설정 화면에 Slack 행 자체는 표시되지만, 활성화하기 전에는 "어댑터 Extension이 설치되어
있지 않습니다" 경고가 뜨고 페어링을 진행할 수 없습니다.

## Slack 앱 생성 및 Socket Mode 설정

1. https://api.slack.com/apps?new_app=1 에서 새 앱을 만듭니다.
2. 앱 설정 **Socket Mode**를 켭니다(별도 공개 HTTP 엔드포인트 불필요).
3. **Basic Information** 하단에서 `connections:write` scope로 **App-Level Token**(`xapp-`)을 생성합니다.
4. **OAuth & Permissions**의 Bot Token Scopes에 최소 `chat:write`(답변 전송), `app_mentions:read`(멘션
   수신), `users:read`를 추가하고, DM도 쓸 경우 `im:history`를 추가합니다. 봇 토큰(`xoxb-`)을 발급받습니다.
   `users:read`는 대화 권한이 아니라 — Core가 `auth.test`→`bots.info` 순으로 호출해 **이 토큰이 실제로
   어느 앱·워크스페이스의 봇인지 스스로 검증**하는 데만 씁니다(공식 문서: `bots.info`는 Bot 토큰이라도
   `users:read` 없이는 호출이 거부됩니다 — https://docs.slack.dev/reference/methods/bots.info/).
5. **Event Subscriptions**에서 `app_mention`, `message.im`을 구독합니다.
6. 워크스페이스에 설치(Install to Workspace)하고, **봇 토큰과 App-Level 토큰 둘 다**를 Desktop 채널
   설정에 붙여넣습니다(Desktop이 실제로 요구하는 값은 이 두 개뿐입니다).

(공식 문서: https://docs.slack.dev/apis/events-api/using-socket-mode/)

## 페어링 (Desktop 승인 필수 — 임의의 첫 메시지로는 절대 열리지 않음)

Slack은 입력창에서 `/`로 시작하는 메시지를 앱에 전달하기 전에 자체 슬래시 명령으로 먼저 가로챕니다 —
`/pair`가 Slack에 등록된 명령이 아니므로, **DM·채널 어디서든 `/pair <코드>`를 그대로 보내면 Slack이
자체적으로 막고 Core에는 아무것도 도달하지 않습니다.**

봇을 먼저 멘션해 메시지가 `/`로 시작하지 않게 만드세요(`@검증된-봇 /pair <코드>`) — Core가 이 멘션이
정말 이 봇 자신을 가리키는지 검증한 뒤 벗겨내는 정규화가 구현되어 있고, 패킹된 아티팩트로 이 흐름이
확인됐습니다. 새 엔드포인트나 Slack 슬래시 명령 등록은 필요 없습니다.

절차는 다음과 같습니다:

1. Desktop 채널 설정에서 **"허용 범위"**(프로젝트/머신/기존 세션/허용 작업)를 먼저 선택합니다. 비워두면
   이후 어떤 명령도 실행되지 않는 그랜트가 만들어지므로, 코드를 발급하기 전에 반드시 지정하세요.
2. 두 토큰을 저장한 뒤 나타나는 **"페어링 코드 발급"** 버튼을 누릅니다.
3. Desktop이 보여주는 일회용 코드를 Slack에서 `@검증된-봇 /pair <코드>` 형태로 봇을 멘션해 보냅니다
   (DM·채널 모두).
4. Desktop의 **"승인 대기"** 항목에 보낸 사람·대화·스레드 정보가 표시됩니다. 여기서 **"승인"**을 눌러야만
   연결이 완료됩니다 — 코드를 보낸 것만으로 자동 승인되지 않습니다.
5. 코드는 몇 분 안에 만료되고 1회만 사용할 수 있습니다.

## 사용 가능한 명령

`/`로 시작하는 명령(`/new`, `/use`, `/status`, `/stop`, `/projects`)은 **DM·채널 모두 봇을 멘션한 뒤**
보내세요(`@검증된-봇 /status`) — 메시지가 `/`로 시작하지 않아야 Slack이 자체 슬래시 명령으로 가로채지
않기 때문입니다. 채널은 Event Subscriptions가 `app_mention`만 구독하므로 멘션이 어차피 필수입니다.
명령이 아닌 일반 대화(이미 선택된 세션에 대한 후속 프롬프트)는 `/`로 시작하지 않으므로 DM에서는 멘션
없이 그대로 입력해도 Slack에 가로채이지 않습니다.

아래 중 `/pair`·`/projects`·`/use`(`/select`)·일반 프롬프트 경로는 패킹된 아티팩트 기준 통합 테스트로
직접 확인됐습니다. 나머지 명령은 같은 파싱 경로를 공유하지만 개별 케이스로 확인한 것은 아닙니다.

| 명령 | 별칭 | 동작 |
|---|---|---|
| `/projects` | | 접근 가능한 프로젝트 목록 |
| `/new <프로젝트ID 또는 이름> [--agent 값] [--model 값] [--effort 값]` | `/start ...` | 새 세션 생성. **프로젝트를 반드시 지정해야 하며, 생략하면 거부됩니다** |
| `/use <세션ID>` | `/select <세션ID>` | 기존 세션 선택. **세션ID를 반드시 지정해야 하며, 생략하면 거부됩니다** |
| `/status` | | 현재 세션 상태 확인 |
| `/stop` | | 진행 중인 턴 중단 |
| `/clear` | `/reset` | 이 대화가 따라가던 세션에서 빠져나옵니다. **세션은 계속 실행됩니다** — `/stop` 과 다릅니다. 다음 메시지는 새 대화에서 시작합니다 |
| (명령 없는 일반 텍스트, DM만) | | 선택된 세션에 대한 후속 프롬프트 |

승인 대기가 필요한 작업은 메시지에 승인/거부 버튼이 함께 표시됩니다(Core 연결 완료 후 동작).

## 평문 메신저 경계

- Slack으로는 해당 요청의 최종 답변과 접수/진행 상태만 전송됩니다. 과거 transcript, 원본 tool 출력,
  환경변수, 첨부파일은 자동 전송되지 않고, 첨부파일 다운로드 자체가 이번 범위에 없습니다.
- Slack 메시지는 Saycode의 종단간 암호화 구간 밖의 평문 메신저입니다.

## 상시 실행

Desktop 앱이 종료되면 이 채널도 함께 멈춥니다(현재 단계). Desktop 없이 계속 수신하는 별도 실행 위치는
이후 단계로 계획되어 있고, 아직 포함되지 않았습니다.

## 문제 해결

| 증상 | 확인할 것 |
|---|---|
| 소켓이 연결되지 않음 | App-Level 토큰에 `connections:write` scope가 있는지 확인 |
| Core의 앱/워크스페이스 신원 확인이 `missing_scope`로 실패 | 봇 토큰에 `users:read`가 빠져 있으면 `bots.info` 호출 자체가 거부됩니다 — Bot Token Scopes에 `users:read` 추가 후 앱을 워크스페이스에 재설치(스코프 추가는 재설치가 필요) |
| `/pair`나 `/명령`을 봇 멘션 없이 그대로 보냈는데 Slack이 자체적으로 "not a valid command" 오류를 보임 | 예상된 동작입니다 — 반드시 봇을 먼저 멘션하세요(`@검증된-봇 /pair <코드>`), 그래야 메시지가 `/`로 시작하지 않아 Slack이 가로채지 않습니다 |
| 봇이 반응 없음 | Desktop에서 "승인" 완료했는지 확인 — 자동 승인 아님 |
| `/new`를 보냈는데 거부됨 | 프로젝트ID/이름을 반드시 함께 입력 |
| `/use`나 `/select`를 보냈는데 거부됨 | 세션ID를 반드시 함께 입력 — 생략하면 일반 대화로 넘어가지 않고 거부됩니다 |
| 답장이 전혀 안 옴 | `chat:write` scope 확인 |
