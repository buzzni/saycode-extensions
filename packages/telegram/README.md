# Saycode Telegram 채널 (`buzzni.telegram`)

전용 테스트 봇의 long-poll로 Saycode 세션을 시작·이어가는 Extension입니다.

**현재 상태**: SDK 단위 테스트·패킹 완료. Desktop Core 쪽 배선은 별도 진행 중이며, 실제 연결 가능 여부는
Desktop 채널 설정 화면에서 확인하세요.

## 준비물

- 이 용도로만 쓸 전용 Telegram 봇(팀·개인 봇과 공유하지 않음).
- Desktop에 로그인된 Saycode 계정.

## Desktop에 설치

이 폴더를 패키징한 `.saycode-extension` 파일을 전달받았다면, Desktop **설정 → 확장 → 로컬 파일 설치**로
설치한 뒤 **활성화**를 눌러 요청 권한을 확인하고 승인하세요(확장 ID: `buzzni.telegram`). 설치·활성화
전에도 "메신저 채널" 설정 화면에 Telegram 행 자체는 표시되지만, 활성화하기 전에는 "어댑터 Extension이
설치되어 있지 않습니다" 경고가 뜨고 페어링을 진행할 수 없습니다.

## 봇 생성 (BotFather)

1. [@BotFather](https://t.me/BotFather)에서 `/newbot`을 보내고 이름·사용자명(`bot`으로 끝나야 함)을 정합니다.
2. 발급되는 **봇 토큰**을 Desktop 채널 설정에 붙여넣습니다. long polling 방식이라 이 토큰 외의 별도 scope나
   webhook 설정은 필요 없습니다.
3. 현재 검증된 경로는 **봇과의 1:1 대화(DM)**입니다. 그룹 채팅 추가나 Privacy Mode 변경은 필요하지
   않으며, 지금 단계에서는 권장하지 않습니다.
   (공식 문서: https://core.telegram.org/bots/features#botfather)

## 페어링 (Desktop 승인 필수 — 임의의 첫 메시지로는 절대 열리지 않음)

1. Desktop 채널 설정에서 **"허용 범위"**(프로젝트/머신/기존 세션/허용 작업)를 먼저 선택합니다. 비워두면
   이후 어떤 명령도 실행되지 않는 그랜트가 만들어지므로, 코드를 발급하기 전에 반드시 지정하세요.
2. 봇 토큰을 저장한 뒤 나타나는 **"페어링 코드 발급"** 버튼을 누릅니다.
3. Desktop이 보여주는 일회용 코드를 Telegram에서 봇에게 `/pair <코드>` 형태로 보냅니다.
4. Desktop의 **"승인 대기"** 항목에 보낸 사람·대화·스레드 정보가 표시됩니다. 여기서 **"승인"**을 눌러야만
   연결이 완료됩니다 — 코드를 보낸 것만으로 자동 승인되지 않으며, "거절"을 누르면 취소됩니다.
5. 코드는 몇 분 안에 만료되고 1회만 사용할 수 있습니다.

## 사용 가능한 명령

| 명령 | 별칭 | 동작 |
|---|---|---|
| `/projects` | | 접근 가능한 프로젝트 목록 |
| `/new <프로젝트ID 또는 이름> [--agent 값] [--model 값] [--effort 값]` | `/start ...` | 새 세션 생성. **프로젝트를 반드시 지정해야 하며, 생략하면 거부됩니다**(기본 프로젝트로 대체되지 않음) |
| `/use <세션ID>` | `/select <세션ID>` | 기존 세션 선택. **세션ID를 반드시 지정해야 하며, 생략하면 거부됩니다** |
| `/status` | | 현재 세션 상태 확인 |
| `/stop` | | 진행 중인 턴 중단 |
| (명령 없는 일반 텍스트) | | 선택된 세션에 대한 후속 프롬프트 |

그룹에서는 `/명령@봇사용자명` 형태도 인식됩니다.

## 평문 메신저 경계

- Telegram으로는 해당 요청의 최종 답변과 접수/진행 상태만 전송됩니다. 과거 transcript, 원본 tool 출력,
  환경변수, 첨부파일은 자동 전송되지 않고, 첨부파일 다운로드 자체가 이번 범위에 없습니다.
- Telegram 메시지는 Saycode의 종단간 암호화 구간 밖의 평문 메신저입니다.

## 상시 실행

Desktop 앱이 종료되면 이 봇도 함께 멈춥니다(현재 단계). Desktop 없이 계속 수신하는 별도 실행 위치는
이후 단계로 계획되어 있고, 아직 이 패키지 범위에 없습니다.

## 문제 해결

| 증상 | 확인할 것 |
|---|---|
| 봇이 반응 없음 | Desktop에서 "승인" 완료했는지, 연결 상태가 "연결됨"인지 확인 |
| `/pair` 후에도 계속 대기 중 | Desktop "승인 대기"에서 직접 승인해야 함 — 자동 승인 아님 |
| `/new`를 보냈는데 거부됨 | 프로젝트ID/이름을 반드시 함께 입력(`/new 내프로젝트`) |
| `/use`나 `/select`를 보냈는데 거부됨 | 세션ID를 반드시 함께 입력(`/use sess-42`) — 생략하면 일반 대화로 넘어가지 않고 거부됩니다 |
