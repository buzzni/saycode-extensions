# Claude에게 moai를 맡기는 법

이 페이지는 **사람이 Claude(어느 세션이든)에게 어떻게 말하면 moai 이슈·마일스톤·백로그를 알아서 다뤄 주는지**, 그리고 그때 Claude가 실제로 무엇을 실행하는지를 정리한다. 직접 명령을 외울 필요는 없다. 아래 "이렇게 말하면" 문장을 그대로 써도 되고, 의미만 맞으면 된다.

- 근거: moai 스킬 4종(`moai`, `moai-supervise`, `moai-tmux`, `moai-recover`)과 `moai --help`, 2.0 마일스톤(`se-9inv`)을 진행하며 트래커 노트에 남은 일들.
- 작성일: 2026-10-15

## 0. 먼저 버전을 확인한다

이 페이지는 **moai 0.17**을 기준으로 쓴다. 이 컴퓨터의 PATH에 있는 `moai`는 0.8.0일 수도 있고(오늘 `moai --version`이 0.8.0을 냈다), 0.8.0에는 없는 명령이 있다. 그런 명령에는 "(0.17+)"를 붙였다.

```sh
moai --version      # 가장 먼저
moai --help         # 이 버전에 있는 명령
moai <명령> --help  # 플래그는 도움말이 정답이다
```

| 명령 | 0.8.0 | 0.17 |
|---|---|---|
| `add`, `edit`, `rm`, `defer`, `link`, `note`, `archive`, `backlog add/promote`, `milestone add`, `show`, `stats` | 있다 | 있다 |
| `moai models` (역할별 모델 표를 JSON으로) | **없다** (`unrecognized subcommand`) | 있다 |

0.8.0이면 `moai models`가 안 되므로, 역할별 모델은 사람이 말로 정하거나 사용자 설정 `[models]` 표를 직접 읽는다.

## 1. 이슈 만들기

### 말하는 법

- "이거 이슈로 만들어 줘. 버그고 p1이야."
- "방금 본 문제를 E5 에픽에 이슈로 넣어 줘."
- "이 작업을 se-ab12 아래 자식 이슈로 만들어."
- "이 기능 계획을 에픽 하나와 이슈 여섯 개로 쪼개서 보여 줘. 내가 OK하면 만들어."

### Claude가 실행하는 것

제목은 인자로, 본문은 표준입력(`-b -`)으로 따로 준다.

```sh
moai add '빈 태그가 필터를 통과한다' -p 1 -t bug -e se-ab12 -b - <<'BODY'
- 무엇: 태그를 정규화하면 빈 단어가 남는다
- 본 것: 그 태그로 거른 목록이 아무것도 거르지 않고 전부 돌려준다
- 고칠 곳: 태그 정규화 지점(<파일>:<줄>). 빈 단어를 버리면 끝난다
BODY
```

| 플래그 | 뜻 |
|---|---|
| `-p 0..3` | 우선순위. 0이 가장 높다. 긴급함은 이모지가 아니라 여기에 쓴다 |
| `-t bug,docs` | 태그. 쉼표로 잇거나 여러 번 준다 |
| `-e <에픽>` | 이 에픽의 멤버로 만든다 |
| `--parent <이슈>` | 그 이슈의 자식으로 만든다. id가 `<부모>.xxx`가 되고 부모의 에픽에 속한다 |
| `-b -` | 본문을 표준입력에서 읽는다 (`-b <텍스트>`의 텍스트는 파일 경로가 아니다) |

### 제목과 본문 규칙

- 제목은 한 줄로 짧게 쓴다. 보드·`ready`·탐색기 목록은 제목만 보여 주므로 긴 사연은 잘린다.
- 본문은 서술이 아니라 목록이다. "무엇이 잘못됐나 / 무엇을 봤나 / 어디를 고치나"로 나눈다. 다음 세션이 `moai show <id>` 한 번으로 읽는다.
- 제목을 본문에 되풀이하지 않는다. 이모지는 제목에도 본문에도 쓰지 않는다(터미널마다 폭이 달라 표가 틀어진다).

### 에픽 + 이슈 3~7개로 쪼갤 때

요청이 파일 하나로 안 끝나면 Claude는 코드를 쓰기 전에 **계획을 한 번 보여 주고 묻는다.** 사람이 yes 하면 한 번에 만든다.

```sh
moai add --from - --dry-run <<'PLAN'     # 먼저 만들어질 모양만 본다
# 목록 정렬 안정화
- [p1] 정렬 키를 id로 한 번 더 묶는다 #bug
- [p2] 정렬 상태를 URL에 저장한다 #enhancement
- 회귀 테스트를 더한다 #test
PLAN
```

그다음 `--dry-run`을 빼고 같은 입력을 준다. `#` 줄이 에픽, `-` 줄이 이슈이고 `[pN]`과 `#태그`는 선택이다. 에픽이 왜 한 묶음인지는 `--body`로 쓴다(첫 에픽에 붙는다).

```sh
moai add --from plan.md --body - < why.md      # 계획은 파일, 본문은 stdin
moai add --from - --body '묶음의 이유'          # 계획은 stdin, 본문은 텍스트
```

`--body -`와 `--from -`는 동시에 stdin을 읽을 수 없다.

## 2. 이슈 정리

### 말하는 법

- "지금 어떻게 돼 가? 뭐부터 하면 돼?"
- "todo에 있는 버그만 보여 줘."
- "'정렬' 얘기가 이미 적혀 있는지 찾아 줘."
- "에픽별로 트리로 보여 줘."
- "오래 멈춰 있는 건 뭐야?"
- "이번 주 몇 개 닫았어?"
- "닫힌 지 오래된 건 아카이브로 옮겨 줘."

### Claude가 실행하는 것

```sh
moai status                      # 보드, 경고, 흐름. 세션은 여기서 시작한다
moai ready                       # 지금 집을 수 있는 것 (내 것만, 남의 것은 others)
moai show <id>                   # 본문, 자식, 이력. 왜 이렇게 정했는지는 여기에 있다
moai show -s todo -t bug         # 필터. 쉼표는 or, 같은 플래그 두 번은 and
moai show -g 정렬                # id·제목·태그·본문·노트에서 찾기
moai show --tree                 # 에픽 → 이슈 → 자식
moai show --stale 7              # 현재 칸에서 7일 넘게 멈춘 것
moai show --deferred             # 미룬 것만
moai stats --bucket day --last 14   # 흐름, 리드 타임
moai archive --dry-run           # 먼저 미리 본다
moai archive                     # .moai/archive/<연도>.jsonl 로 옮긴다
```

- **경고는 아무것도 막지 않는다.** 에픽 없는 이슈, 오래 걸린 리뷰, 한꺼번에 열려 있는 수를 비춰 줄 뿐이다. 백로그가 쌓인 것과 미룬 것은 경고가 아니라 알림(`notices`)이다.
- 아카이브는 에픽과 멤버가 통째로 `archive_days`만큼 닫혀 있어야 옮겨진다. 일반 쓰기는 아카이브하지 않으므로 명시적으로 요청해야 한다. 마일스톤은 옮겨지지 않는다.
- 세션을 끝낼 때 Claude는 `moai status`를 한 번 더 보고 경고가 늘었는지 확인한다.

## 3. 합치기

moai에는 **병합 명령이 없다.** 같은 일을 두 이슈가 적고 있으면 사람이 살릴 쪽을 정하고, Claude가 아래 순서로 옮긴다.

### 말하는 법

- "se-aaaa랑 se-bbbb는 같은 일이야. aaaa로 합쳐 줘."
- "se-bbbb는 중복이니까 지워. 내용은 aaaa에 옮기고."
- "se-bbbb는 aaaa가 끝나야 하는 일이야, 순서만 걸어 줘."

### Claude가 실행하는 것

```sh
# 1. 살릴 쪽을 정한다 (사람이 말해 주지 않으면 Claude가 묻는다)
moai show se-aaaa ; moai show se-bbbb

# 2. 본문을 옮긴다. -b 는 본문 전체를 바꾸므로 읽어서 이어 붙인다
{ moai show se-aaaa --json | jq -r '.body // empty'
  printf '\n- se-bbbb 에서 옮김: <사라질 쪽의 핵심 줄>\n'; } | moai edit se-aaaa -b -

# 3. 이력(노트)은 새 노트로 요약해 둔다
moai note se-aaaa 'se-bbbb 합침: <결정과 근거 한 줄>'

# 4. 막힘 관계가 있으면 이어 준다
moai link se-bbbb --blocks se-cccc      # bbbb 가 cccc 를 막는다 → cccc 쪽에 blocked_by 가 쓰인다
moai link se-aaaa --blocks se-cccc      # 살리는 쪽으로 다시 건다

# 5. 남는 쪽을 치운다: 실수·중복이면 rm, 나중에 살필 일이면 defer
moai rm se-bbbb
moai defer se-bbbb -m 'Merged-into: se-aaaa'
```

- **`rm`은 되돌릴 수 없다.** 실수로 만들었거나 완전히 같은 중복일 때만 쓴다. 이력이 의미 있으면 `defer -m 'Merged-into: <id>'`로 남겨 두고 이력으로 길을 잇는다.
- **합치지 말고 `--parent`로 묶는 편이 나은 경우:** 둘이 같은 일이 아니라 "큰 일과 그 조각"일 때. 이슈를 지우지 말고 `moai add ... --parent <큰 이슈>`로 새로 만들거나, 조각을 에픽 멤버로 옮긴다(`moai edit <id> -e <에픽>`).
- 다른 사람이 집은 행은 합치기 전에 먼저 묻는다(4절).

## 4. 지우기

### 세 가지는 다르다

| 하고 싶은 것 | 쓰는 것 | 이유 |
|---|---|---|
| 실수로 만들었다, 중복이다 | `moai rm <id>` | 되돌릴 수 없다. 이력이 같이 사라진다 |
| 하기로 했지만 지금은 아니다 | `moai defer <id> -m '<이유>'` | 칸과 종류가 그대로이고 `--undo`로 같은 행이 돌아온다. 보드·`ready`·경고에서 빠진다 |
| 끝냈다 | `moai mv <id> done` | **하지 않기로 한 일을 `done`으로 옮기지 않는다** |

- 에픽 멤버를 `defer`하는 것은 "에픽이 약속한 것을 포기한다"는 결정이다. 에픽이 이것 없이는 약속을 지킬 수 없다면 `defer`가 아니라 첫 칸에 둔다(멤버가 남아 있으면 에픽이 저절로 닫히지 않는다).
- 에픽·마일스톤은 `mv`하지 않는다. 칸은 멤버에서 읽는다. 포기하려면 멤버를 `defer`하고, 한 번도 끝낸 멤버가 없으면 그룹 자체를 `defer`한다.
- 깨진 줄(읽을 수 없는 행)은 id로 못 닿는다. 줄 번호와 해시로 지운다.

```sh
moai rm --line 812                          # 줄과 해시를 보여 준다
moai rm --line 812 --yes --match 1a2b3c4d   # 지운다. 새 moai가 다시 읽는 줄이면 남겨 둔다
```

### 남의 행은 먼저 묻는다

assignee가 다른 사람이거나 없는 행을 집는 것은 훅 규칙 5가 막는다. Claude는 사람에게 먼저 묻고, yes를 받으면 이렇게 한다.

```sh
moai mv <id> in_progress --from todo --take -m '<누가 yes 했는지>'
```

여기서 `--from todo`는 지금 본 칸이 그대로일 때만 옮기게 하는 안전장치이고, `--take`가 담당자를 나로 바꾸며 `Taken-over: <원래 담당자>` 노트를 남긴다. 여러 id를 한 번에 옮기지 않는다(이긴 것과 진 것이 한 종료 코드에 섞인다).

## 5. 마일스톤

### 말하는 법

- "v2.0 마일스톤 만들어 줘. 10월 말까지."
- "이 계획을 마일스톤에 포함시키고 만들어 줘." (사람이 직접 yes 하는 문장)
- "se-xxxx 에픽을 se-9inv 마일스톤에 넣어."
- "마일스톤에 포함시키고." (이미 만든 행에 대해 한 말)

### Claude가 실행하는 것

```sh
moai milestone add 'v2.0' --start 2026-10-01 --due 2026-10-31
moai add --from - --milestone se-9inv <<'PLAN'     # 계획 전체를 마일스톤에 (에픽에 붙고 멤버가 상속)
# 에픽 제목
- 이슈
PLAN
moai edit <에픽 id> --milestone se-9inv            # 이미 있는 에픽을 넣는다
moai show --milestone se-9inv                       # 마일스톤에 걸린 전부
moai edit <id> --milestone none                    # 빼기. 상속받은 소속은 남는다
```

### 진행 중인 마일스톤은 사람이 채우는 것이다

멤버 중 하나라도 시작된 칸(`in_progress`·`review`)에 있으면 마일스톤은 진행 중이다. 이때:

- `moai ready`는 마일스톤 안의 일만 내주고, 바깥에서는 `p0`만 내준다(핫픽스 자리).
- **바깥의 일은 자동으로 끌려 들어오지 않는다.** 배포 범위는 시작 전에 정해졌기 때문이다. Claude가 `--milestone <진행 중인 것>`을 스스로 붙이지 않는다. 들어가는 문은 세 개다: 사람이 `edit --milestone`으로 붙인다, 계획을 보여 주고 yes를 받은 같은 순간에 붙인다, 작업 중인 멤버에서 나온 일을 그 멤버의 에픽에 만든다(`-e`).
- 사례(2026-10-14): 사람이 "마일스톤에 포함시키고"라고 말했고, Claude는 새 이슈를 마일스톤 안의 에픽에 `moai edit <id> -e <에픽>`으로 올렸다. 사람의 문장이 곧 "붙여도 된다"는 승인이다.
- 막는 것은 없다. 어디까지나 Claude가 지키는 규칙이다.

## 6. 백로그

### `backlog add` 와 `add`

기준은 하나다: **"지금 집어서 하겠는가?"** 하겠다면 `moai add`, 나중이면 `moai backlog add`. 백로그는 보드와 `ready`에 안 올라가므로 계획을 흐리지 않는다. 지나가면서 적지 않고 지나치는 것이 가장 나쁘다.

단, 에픽 안에서 나온 일이면 한 가지를 더 묻는다. **"이것 없이 이 에픽이 약속한 것을 낼 수 있나?"** 못 낸다면 미룰 일이 아니라 이 일의 미완성이다. 지금 못 하더라도(사람의 결정을 기다리거나 파일이 다른 작업에 잡혀 있어서) `-e <에픽>`으로 멤버로 만들고 첫 칸에 둔다. 백로그로 내보내면 에픽은 약속을 못 지킨 채 `done`이 된다.

### 말하는 법

- "이거 백로그로 적어 둬."
- "방금 본 문제, 지금은 못 하니까 백로그로 자세히 남겨 줘."
- "sonnet 5.5로 분석해서 백로그로 자세히 남겨줘."
- "백로그에서 se-xxxx 꺼내서 E5 에픽의 이슈로 풀어 줘."

### Claude가 실행하는 것

```sh
moai backlog add '긴 목록에서 상세 패널이 깜빡인다' -b - <<'BODY'
- 무엇이 잘못됐나: ...
- 본 것: detail.ts:212 에서 행 id가 바뀔 때마다 ...
- 어디서 고치나: ...
- 누가 언제 정했나: 2026-10-15 사람이 "2.1로 미룬다"고 결정
BODY
moai backlog ls
moai show -g 깜빡

# 풀 때: 짧은 새 제목으로 쓴다 (계획 줄이 그대로 제목이 된다)
moai backlog promote <id> --from - --dry-run <<'PLAN'
# 상세 패널 안정화
- [p1] 행 id가 같으면 상세를 다시 그리지 않는다 #bug
PLAN
moai backlog promote <id> -e <에픽> --from - <<'PLAN'   # 이미 있는 에픽의 멤버로 풀 때
- [p1] 에픽이 약속한 것 중 빠진 부분
PLAN
```

- `promote`는 원본 백로그를 `done`으로 닫고 이력에 어디서 풀렸는지 남긴다. 풀린 에픽에는 백로그의 마일스톤과 본문이 따라간다(`-e`로 기존 에픽에 풀 때는 따라가지 않는다).
- 백로그가 진행 중인 마일스톤이 아닌 곳에 서 있으면 에픽이 마일스톤 바깥에 선다. 마일스톤에 넣을지는 사람이 정한다: `moai edit <에픽> --milestone <id>`.

### 자세한 설명은 어느 모델이 쓰나

역할별 모델은 사람의 사용자 설정 `[models]` 표에서 읽는다. 0.17+에서는 `moai models --json`이 보여 준다(0.8.0에는 없다). 역할은 `plan` · `develop` · `complex` · `review` · `docs` · `bulk` · `codex`다.

| 일 | 역할 | 말하는 법 |
|---|---|---|
| 자세한 백로그 본문, 위키·CHANGELOG | `docs` (또는 `plan`) | "docs 모델로 백로그 자세히 써 줘" |
| 분석이 무거운 백로그 (원인 추적, 계약 비교) | `complex` 또는 `review` 급 = 보통 opus | "opus로 분석해서 백로그로 남겨 줘" |
| 에픽을 이슈로 쪼개기 | `plan` | "plan 모델로 쪼개 줘" |
| 같은 수정 반복, 긴 텍스트 요약 | `bulk` | "bulk로 정리해" |

모델을 직접 말해도 된다: "sonnet 5.5로 분석해서 백로그로 자세히 남겨줘". 세션의 모델은 메시지로 못 바꾸므로(사람이 `/model`로 바꾼다), 다른 모델이 필요하면 Claude가 그 모델로 서브에이전트를 올려 쓴다.

### 좋은 백로그 본문에 들어 있는 것

다음 사람이 이것만 읽고 집을 수 있어야 한다.

- 무엇이 잘못됐나 (증상과 영향)
- 무엇을 봤나 (`파일:줄`, 재현 순서, 측정값)
- 어디서 고치나 (후보 위치, 건드리면 안 되는 곳)
- 누가 언제 무엇을 정했나 (결정과 날짜, 미룬 이유)

## 7. 스킬 사용 팁

| 스킬 | 언제 | 요약 |
|---|---|---|
| `moai` | 이슈·계획·할 일 전반 | 위 1~6절의 규칙과 훅 5가지 |
| `moai-supervise` | 쌓인 백로그를 일꾼에게 하나씩 나눠 줄 때 | 감독자는 고르고 보내고 확인한다. 코드는 고치지 않고 병합은 일꾼이 한다 |
| `moai-tmux` | 감독자가 tmux 안에 있을 때 | 일꾼 칸 찾기·이름표·비우기 |
| `moai-recover` | 재시작·OOM·충돌 뒤 | 죽은 세션을 찾아 `--resume`으로 새 칸에 되살린다 |

### moai-supervise: 일꾼은 세션인가 서브에이전트인가

- 기본 일꾼은 감독자가 `Agent`로 올리는 서브에이전트다. 사람이 일꾼 창을 보고 싶어 하거나 Codex 작업이면 일꾼은 세션이다.
- **"서브에이전트로 해 줘"는 "일꾼 세션이 안에서 서브에이전트를 쓰라"는 뜻이다.** 감독자가 서브에이전트가 되라는 말이 아니다(감독자는 세션이고 일꾼도 세션이다).
- 저장소당 감독자는 하나다. 다른 창에서 이미 감독 중이면 두 번째 감독자는 일을 받지 않고 사람에게 알린다.
- 서브에이전트 일꾼이 집은 행은 감독자가 건드리지 않는다(훅이 그 호출을 감독자의 것으로 읽기 때문이다).

### moai-tmux: 칸 다루기

- 칸 이름표는 pane 옵션 `@moai`에 붙는다. 테두리에 보여 줄지는 한 라운드에 한 번 사람에게 묻는다.
- `/clear`는 **일꾼이 한가하고 보고가 확인됐고 입력창이 비어 있을 때만** 보낸다. 입력창에 뭔가 있으면 사람의 글이니 건드리지 않는다.
- 사람이 칠 자리에 대신 치지 않는다. 권한 창이나 질문은 사람의 몫이고 Claude는 읽어서 알려 주기만 한다.
- 칸을 폴링하지 않는다. 화면은 한 번 보고, 다음 단계 뒤에 다시 본다. 칸·세션을 죽이지 않는다(`kill-server` 등은 훅이 막는다).

### 이번 마일스톤(se-9inv)에서 배운 것

**세션이 같은 git 사용자를 공유한다**

- 모든 세션이 같은 git user라서 훅 규칙 1·3과 Stop 훅이 다른 세션의 행을 내 것으로 읽는다. 그 결과 `moai add -e`나 `backlog promote`가 거부되는 일이 있었다.
- 쓴 우회: `moai backlog add`로 먼저 적고, `moai edit <id> -e <에픽>`으로 에픽에 올리고, 일꾼은 백로그 행을 바로 집는다.
- **집지 않은 행은 Stop 훅이 요구해도 옮기지 않는다.** 한 일꾼이 그 요구에 따라 남의 행 5개를 todo로 돌려놓은 적이 있다.

**일꾼이 입력을 기다리며 멈춘다**

- 한 일꾼이 `/model opus`를 4시간 기다렸다(세션 모델은 메시지로도 설정으로도 못 바꾼다). 일꾼에게는 "리뷰는 opus 서브에이전트로 돌려라"고 쓴다.
- 시계가 멈춘 낡은 서브에이전트 항목이 `ListAgents`에 남아 일꾼이 아직 일하는 것처럼 보인 적이 있고, 입력(stdin)을 기다리며 매달린 백그라운드 셸(`cat`)이 일을 붙든 적도 있다. 둘 다 "한가해지지 않는 일꾼"으로 나타난다. 어떻게 찾아 치웠는지의 세부는 트래커 노트(se-0g4a, se-89fu, se-bz5y, se-pbqz, se-ehdi 이력)에 있고 이 페이지에는 옮기지 않았다. 확인한 것: 감독자가 보고를 못 받으면 먼저 그 일꾼 상태를 한 번 읽고, 사람에게 알린 뒤에 정리한다.

**워크트리와 git**

- 새 워크트리에는 `node_modules`가 없다. 테스트 전에 `npm ci`.
- `git branch -d`는 지금 HEAD에 병합됐는지를 본다. 마일스톤에 병합한 브랜치는 **마일스톤 워크트리에서** 지운다(루트에서 하면 "not fully merged"가 난다).
- `.moai`가 git에서 제외돼 있을 수 있다. 그러면 트래커 쓰기는 디스크에만 있고 커밋되지 않는다. 트래커 커밋을 만들려 하지 않는다.

**입력과 환경**

- `!명령`은 프롬프트의 **첫 글자**여야 쉘 명령으로 실행된다.
- Happy 데몬은 쉘의 moai가 아니라 자기가 관리하는 moai(`~/.happy/managed-tools/buzzni.moai/0.8.0`)를 쓴다. 패널이 보는 것은 지금 CLI에서 시험하는 것과 다를 수 있다. 버전 차이로 안 되는 기능은 이 경로의 버전부터 확인한다.
- 자동 모드 분류기가 어떤 편집이나 명령을 거부하면 **멈추고 보고한다.** 다른 길로 돌려서 하지 않는다. 사람이 허용하거나 결정한다.

## 8. 한 번에 보는 말 → 명령

| 이렇게 말하면 | Claude가 하는 것 |
|---|---|
| "이슈로 만들어" | `moai add '<짧은 제목>' -b -` |
| "에픽으로 쪼개 줘" | 계획을 보여 주고 묻고, yes면 `moai add --from -` (`--dry-run` 먼저) |
| "지금 어때?" | `moai status`, `moai ready` |
| "이거 이미 적혀 있나?" | `moai show -g <키워드>` |
| "이 둘 합쳐" | 살릴 쪽 정하기 → `edit -b -`, `note`, `link --blocks` → `rm` 또는 `defer -m 'Merged-into: …'` |
| "이건 안 하기로 했어" | `moai defer <id> -m '<이유>'` (`done` 아님) |
| "마일스톤에 포함시키고" | `moai edit <id> -e <마일스톤 안의 에픽>` 또는 `--milestone` |
| "나중에 하자" | `moai backlog add '<제목>' -b -` |
| "백로그 풀어 줘" | `moai backlog promote <id> --from -` |
| "일꾼들 일 시켜" | `moai-supervise` |
| "세션 되살려" | `moai-recover` |
