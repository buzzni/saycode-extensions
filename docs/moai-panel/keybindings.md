# Moai 패널 단축키 매핑

moai TUI의 단축키를 세이코드 패널에서 같은 키로 지원할 수 있는지 키마다 판정한다. 원본 키 표는 `moa-issue/src/tui/keys.rs`(BROWSE 657, MENU 1222, PROMPT 1250, SORTER 1283, WIKI 1448)에 있다. 전체 명세는 [moai TUI 분석](tui-analysis.md)에, 계획은 [개편 계획](overview.md)에 있다.

> **구현 후 표시 (2026-10-14).** 판정 표는 구현 **전**의 설계이고 본문은 그대로 둔다. 키 표(`panel/keys/table.ts`)와 라우터(`router.ts`)는 마일스톤 `milestone/se-9inv`에 머지됐고(`4d8ae65`), 아래 "구현과 달라진 점"에 판정과 다른 곳을 모았다. 키 라우터는 배선 묶음(`a7fe3df`)에서 패널에 이어져 **단일 키 주인**이 되었다.

## 구현 상태와 달라진 점

### 머지된 것

- `keys/table.ts`: 모드별(browse·wiki 등) 바인딩, 라벨, 상태 라벨을 **데이터**로 둔 키 표. SPC 메뉴 격자와 도움말 오버레이를 이 표에서 만든다.
- `keys/router.ts`: keydown → 시퀀스 버퍼(`gg`, `SPC …`) → 액션. 입력창·IME 억제, `preventDefault` 집합, 메뉴 밖 이동 키 통과, 토글 항목 뒤 메뉴 유지는 2절 규칙대로다.
- `view/menu.ts`(SPC 메뉴), `view/help.ts`(`?` 도움말, 모달).
- 키 표는 제외한 키(`0`~`9`, `SPC g s`, `SPC q`, `Ctrl-C` 등)를 갖지 않고, `Ctrl-w` 대체는 macOS에서만 원래 키를 받는다는 판정을 따른다.

### 리뷰에서 판정과 달라진 것 (`se-pbqz.ygb`, 10건 반영)

| 항목 | 설계 판정 | 구현 |
|---|---|---|
| 자동 반복 | 규정 없음 | `event.repeat`는 버린다. `SPC`를 누르고 있어도 메뉴가 깜박이지 않고, 토글 키가 반복해서 뒤집히지 않는다 |
| 모드 전환 | 규정 없음 | 시퀀스 중에 모드(browse ↔ wiki)가 바뀌면 들고 있던 시퀀스와 메뉴 층을 버린다 |
| 도움말이 열린 동안 | 규정 없음 | `aria-modal` 안의 키는 라우터가 무시한다. 닫으면 포커스를 되돌린다 |
| `SPC v 1~9` 도움말 라벨 | | `1~9번째 칸` 한 줄로 쓴다 |
| 위키의 `SPC w j/k` | 3.3·3.6절이 `SPC w`를 공통으로 적음 | **browse에서만** 둔다. 위키 탭은 늘 좌우 분할이라 j/k가 없다 |

### 배선 묶음에서 정리된 것 (`a7fe3df`, 리뷰 `se-pbqz.y8z`)

- **키 주인은 라우터 한 곳이다.** 목록·칸반·위키·툴바가 따로 처리하던 keydown(E3 리뷰 `se-c10x.7z7`)을 정리했다. 필터 입력의 `Esc`/`S-Tab`도 라우터로 간다.
- **버튼의 `Enter`/`Space`**: 포커스된 버튼·체크박스·라디오·range에서는 컨트롤이 키를 가진다. 상세를 닫던 `detail.focus()`는 닫기 버튼이 아니라 창을 포커스한다.
- **SPC 메뉴·도움말·kbd 힌트**가 이어졌다. 도움말이 열린 동안 라우터는 조용하다. 토글 뒤 상태 라벨은 스토어가 바뀔 때 다시 그린다.
- **한글 입력 소스**: 글자 키가 `ㅓ`·`Process`로 오면 `event.code`의 US 배열 글자로 읽는다(`ab59484`, `se-pbqz.k84`). **실기 확인은 남았다.**
- **위키 키**: 라우터가 `wiki.handleKey`를 `standaloneKeys: false`로 부른다. `Esc`가 지울 것이 없으면 셸이 포커스를 탭 바로 옮긴다. `SPC v r`은 `wiki.toggleRaw()`에 묶였다.
- **읽음 키**: `r`, `SPC m a`, `SPC m g`가 `read`·`read-all`·`read-group`을 부르고 쓰고 나서 다시 읽는다. NEW 칩과 탭 뱃지가 있고, 쓰고 나면 열린 상세도 다시 읽어 함께 풀린다(`se-ehdi.zcx`).
- **`Shift+Space`/`Shift+Backspace`**: 메뉴 안에서 정확한 토큰 일치라 삼켜진다. 의도가 불분명해 두었다(`se-pbqz.ygb` #10).

### 해결된 것 (`se-h5c7`, `se-gq4i`, `d30fd6c`)

- 도움말이 열린 동안에는 그 뒤의 컨트롤이 받는 키가 가지 않는다. 호스트의 조합(Cmd/Meta, macOS 밖의 Ctrl)은 통과하고(복사 등), Ctrl+Alt와 Enter·Space·Esc·방향키·Home/End·PageUp/PageDown·Backspace/Delete는 막는다(`se-1fy7`, 최종형 `6a1d7ff`).
- `Tab`은 어떤 동작이 쓸 때만 막는다. 핸들러가 키를 브라우저에 맡길 수도 있다. 위키 검색은 `Tab`/`S-Tab`/`↑`을 자기가 쓴다. 위키 모드에서 탭 버튼의 `Tab`은 포커스를 평소대로 옮긴다.
- 포커스된 탭 버튼에서 `SPC`는 SPC 메뉴를 연다.
- 위키 목록에서 `PageDown`/`C-d`는 커서를 옮긴다.
- 모드가 바뀌면 남은 SPC 메뉴가 닫힌다. 필터 제안은 blur 때 닫힌다.
- 포커스 힌트는 오른쪽 아래에 있어 탭 바를 가리지 않는다.

### 아직 남은 것

- 정렬 편집기 `D`(`se-5air`)는 TUI처럼 정렬을 적용하고 기본 정렬로 저장한 뒤 편집기를 닫는다. 기본 정렬은 **세션 동안만** 유지된다. 영속 저장은 SDK 설정 저장 API를 기다린다(`se-c9mu`). 정렬을 비우면 이 기본 정렬로 돌아간다(`State.defaultSort`).
- `SPC v a`는 메뉴에서 짧은 라벨이고 "모두 보이기 (아카이브 제외)"라는 전체 문구는 도움말에 있다. 키 표와 메뉴·도움말 라벨은 en·ko·ja·zh로 나온다(`copy.table`, `se-ti70`). 아카이브는 `SPC v o`로 따로 켠다(TUI와 같음, `se-q0u4`).

### 실기 확인이 남은 것 (스파이크 `se-0g4a.zrf`)

이 페이지 1절과 4절의 세 가지가 **아직 그대로 미확인**이다. 도구 탭에서 iframe 포커스를 얻는 방법, Linux에서 `Ctrl+F/B/U/D`가 패널에 도달하는지, 모달 표면에서 `Esc`의 동작이다.

## 1. 키가 패널까지 오는 경로

조사한 결과(`aplus-dev-studio-desktop` 기준)는 다음과 같다.

- 패널은 `sandbox="allow-scripts"` iframe이다. iframe에 포커스가 있으면 keydown은 iframe 문서에서 처리되고 부모 window로 버블링되지 않는다.
- 앱 renderer의 단축키 핸들러는 모두 `window.addEventListener('keydown')`이고 `isKeybindingMatch`로 **Mod/Alt 조합만** 매칭한다(`src/domain/keybindings.ts:20-85`). 단일 문자 키를 전역에서 가로채는 핸들러는 없다. 그래서 iframe에 포커스가 있으면 renderer 단축키(`Mod+K`, `Mod+F`, `Mod+B`, `Mod+U`, `Mod+S` 등)도 패널로 온다. 이 동작은 코드만 보고 추정한 것이라 실기에서 확인해야 한다(`se-0g4a.zrf`).
- 예외는 두 가지다.
  - **Electron 메뉴 가속기**는 포커스된 프레임과 상관없이 동작한다(`electron/appMenu.ts:46-110`). `CmdOrCtrl+N`, `CmdOrCtrl+R`, `Shift+CmdOrCtrl+R`, 확대·축소(`CmdOrCtrl+=`, `-`, `0`), 전체 화면, 편집 메뉴(`Z`, `Y`, `X`, `C`, `V`, `A`)가 여기에 든다.
  - **`before-input-event`**는 webContents 단위라서 iframe 입력도 먼저 본다. 지금은 `Mod+W`(탭 닫기)만 가로챈다(`electron/windowCloseShortcut.ts:20-40`).
- `Mod`는 macOS에서 Cmd, Linux·Windows에서 Ctrl이다. 그래서 **Linux·Windows에서는 `Ctrl+W`, `Ctrl+N`, `Ctrl+R`, `Ctrl+C/V/X/A/Z/Y`를 패널이 받지 못한다.** macOS에서는 이 Ctrl 조합이 모두 비어 있다.
- 호스트는 도구 탭이 선택될 때 iframe에 포커스를 넘기지 않는다. 사용자가 패널을 한 번 클릭해야 키가 온다. 패널은 로드 직후 `body`(`tabindex=-1`)에 `focus()`를 시도하고, 포커스가 없을 때는 "클릭하면 키보드를 쓸 수 있습니다" 힌트를 보여 준다.

## 2. 패널 쪽 공통 규칙

- 입력창(`input`, `textarea`, `select`, `contenteditable`)에 포커스가 있으면 단일 키 핸들러를 끈다. TUI에서도 글칸 모드에서는 이동 키가 그냥 글자가 된다.
- `event.isComposing`(한글 IME 조합 중)이면 아무 키도 처리하지 않는다.
- Browse 모드에서 `Space`, `Backspace`, `/`는 `preventDefault()`한다. `Tab`은 동작이 쓸 때만 막고, 핸들러가 브라우저에 맡길 수 있다. 브라우저 기본 동작(포커스 이동, 스크롤)을 막기 위해서다.
- 두 키 시퀀스(`gg`, `Ctrl-w w`, `SPC …`)는 키 버퍼로 처리한다. `gg`는 두 번째 키가 `g`가 아니면 버퍼를 버린다. SPC 메뉴는 메뉴에 없는 키를 무시한다. 메뉴 층에 없는 **이동 키**는 메뉴를 닫고 그 이동을 바로 한다(`moa-issue/src/tui/menu.rs`).
- 키 표는 데이터로 둔다. SPC 메뉴 격자와 도움말 오버레이는 이 표에서 자동으로 만든다. TUI도 같은 방식이다.

## 3. 판정 표

판정 기호는 다음과 같다.

| 기호 | 뜻 |
|---|---|
| **같음** | 같은 키로 지원 |
| **확인** | 같은 키로 지원하되 실기 확인이 필요 |
| **대체** | 원래 키 + 대체 키 |
| **변경** | 의미가 바뀜 |
| **제외** | 지원하지 않음 |

### 3.1 이동 (목록·칸반·상세에 공통, 포커스된 패널에 적용)

| TUI 키 | 동작 | 패널 | 비고 |
|---|---|---|---|
| `j` `↓` / `k` `↑` | 한 줄 아래·위 | 같음 | 칸반에서는 칸 안에서 이동 |
| `gg` `Home` / `G` `End` | 맨 위·맨 아래 | 같음 | 칸반에서는 현재 칸의 맨 위·아래 |
| `Ctrl-d` / `Ctrl-u` | 반 페이지 스크롤, 커서는 그대로 | 확인 | `Ctrl+U`는 renderer의 "파일 첨부"(Mod+U)이고 iframe 포커스 중에는 패널로 온다고 본다 |
| `Ctrl-f` `PageDown` / `Ctrl-b` `PageUp` | 한 페이지 스크롤 | 확인 | `Ctrl+F`, `Ctrl+B`는 renderer 단축키라 패널로 온다고 본다. `PageDown`/`PageUp`은 어디서나 된다 |
| 마우스 휠 | 포인터 밑 패널만 스크롤, 커서는 그대로 | 같음 | 화면만 굴리는 "adrift" 의미를 유지하고, 다음 `j`/`k`가 커서 위치로 화면을 되돌린다 |

| `SPC m` 읽음 | `a` `g` | | 같음 |
| `SPC o` 옵션 | `d` | 상세 위치 순환(right→bottom→left→top) | 변경: **왼쪽 ↔ 아래 토글**. 툴바 버튼과 같은 동작 |
| | `t` `m` | 시간대, 마우스 | 제외 |
| `SPC w` 창 | `w W h j k l` | 패널 포커스 | 추가 (3.3절) |
| `SPC ?` 또는 `?` | | 단축키 도움말 | 추가 |

SPC 메뉴 규칙은 TUI와 같다.

- `Esc`나 `SPC`로 닫고, `Backspace`로 한 층 올라간다.
- 토글 항목은 실행한 뒤에도 메뉴를 열어 둔다.
- 지금 상황에서 의미 없는 항목은 메뉴에 나오지 않는다.
- 항목마다 `[shown]`/`[hidden]`, `[asc]`/`[desc]`, `[left]`/`[bottom]` 같은 상태 라벨을 붙인다.
- 메뉴 항목을 클릭하면 그 키를 누른 것과 같다.

### 3.9 정렬 편집 팝오버

`j`/`k` 이동, `J`/`K` 순서 바꾸기, `SPC` 넣기·빼기, `d` 방향 반전, `Enter` 적용, `D` 기본값으로 저장, `Esc` 취소. 모두 **같음**이다. 마우스로는 드래그와 체크박스를 쓸 수 있다.

## 4. 결론

- TUI 키 대부분(이동, 드나들기, 검색, 필터, SPC 메뉴 전체, 위키 키)은 **같은 키로 지원할 수 있다.**
- 막히는 것은 `Ctrl-w` 계열뿐이다. Linux·Windows에서는 Desktop의 `before-input-event`가 가로챈다. `SPC w`를 대체 키로 두고, macOS에서는 원래 키도 받는다.
- `Ctrl-d/u/f/b`는 코드만 보면 패널로 온다. 실기 스파이크 `se-0g4a.zrf`에서 확인한다. 막히면 `PageDown`/`PageUp`과 `SPC` 접두 대체 키를 둔다.
- 반드시 실기로 확인할 것:
  1. 도구 탭에서 iframe 포커스를 얻는 방법
  2. `Ctrl+F/B/U/D`가 패널에 도달하는지 (Linux)
  3. 모달 표면에서 Esc가 어떻게 동작하는지
